# ADR-010 — Development SSO Loopback Callback

**Status:** accepted
**Date:** 2026-07-12
**Author:** developer

---

## Context

Packaged Fikr Studio owns the `fikr-studio://` protocol. Development Studio runs through the generic Electron executable and deliberately does not register that protocol, because doing so would steal the packaged application's system-wide callback. As a result, a login started by development Studio launches the installed app, whose process does not own the initiating OAuth state, and the callback is rejected.

---

## Decision

Development Studio will receive fikr.one SSO through a one-shot HTTP listener bound to an ephemeral `127.0.0.1` port. Packaged builds continue to use the registered `fikr-studio://auth/callback` deep link.

The fikr.one login page accepts loopback desktop return URLs only in a non-production build. The callback must match the exact loopback origin and path generated by Studio, contain one valid state and one token, and arrive before expiry.

**Alternatives considered:**
- Register `fikr-studio://` from development Electron — rejected because the generic Electron executable can steal callbacks from the installed app.
- Share pending auth state between installed and development apps — rejected because it couples separate processes and creates a persistent sensitive handoff.

---

## Consequences

**Positive:**
- Fresh login works in development without changing the packaged protocol owner.
- Tokens are delivered only to a one-shot listener on the local machine.
- Production SSO behavior remains unchanged.

**Trade-offs / New constraints:**
- Development login requires the local fikr.one server.
- The loopback listener must be closed after success, expiry, retry, or app shutdown.
